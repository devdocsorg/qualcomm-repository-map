Map dataset

repositories.json is the sole maintained source of repository facts and relationships. The generator validates it before producing any output.

Schema

| Field | Type and meaning | | --- | --- | | schema_version | Required integer, currently 1; unsupported versions fail. | | scope | Required string defining the inventory scope and expansion boundary. | | inventory_source, inventory_observed | Required source URL and observation date for the repository inventory; these do not date every edge. | | coverage | Required string explaining the limits of relationship review. | | repositories | Required list of unique repository records. | | Repository id, url | Required owner/name identifier and canonical HTTPS repository URL. | | Repository description, group | Required purpose and editorial browsing group; groups do not assert dependencies. | | Repository branch | Default branch string, or null if not inventoried; not a build revision. | | Repository archived | Required boolean for inventory status. | | relationships | Required list of directed relationships. | | Relationship from, to, kind | Required repository IDs and a supported type declared in the generator. Both endpoints must exist. | | Relationship local_summary | Optional short reader-facing purpose, required for relationships included in a local export. | | Relationship condition | Required string describing branch/release applicability, optionality, and indirect paths where relevant. | | Relationship evidence | Non-empty list of records with a url, 40-character commit revision, and claim supported by that source. |

No implicit environment settings, URL rewrites, or network requests change the data at build time. Update inventory metadata when refreshing the organisation listing; review relationship evidence independently. Do not copy upstream documentation into descriptions or infer edges from names.

Files

  • README.md — Defines the dataset schema and evidence rules.
  • repositories.json — Owns repository records and reviewed relationships.

Update the map

Use Python 3.12 or newer and uv. From the repository root:

uv venv .venv
uv pip install --python .venv/bin/python -r tools/requirements.txt
.venv/bin/python tools/map_build.py
.venv/bin/python tools/check_map.py

Edit the dataset and regenerate; commit the dataset and generated views together. Repository names link directly to their repositories. Explore links navigate the map. All evidence and branch conditions belong in this dataset.

To export a nearby view from a committed dataset and generator:

.venv/bin/python tools/map_build.py --export qualcomm-linux/meta-qcom-3rdparty \
  --destination ../meta-qcom-3rdparty/docs/source/user \
  --revision "$(git rev-parse HEAD)"

The export writes a compact REPOSITORY_MAP.md: the current repository once, a linked table of build dependencies and inputs, and one link to the full details. Set local_summary on each exported relationship to explain its role briefly, including required, optional, board-specific, or indirect applicability. CI automation and incoming users stay in the full map. The source revision and dataset digest are recorded in an HTML comment rather than reader-facing prose. Rebuild the recipient's documentation site after replacing the snapshot. Access to this private repository is required to update the map; exported public repository links work independently.

Python's native pydoc reads the generator's function documentation:

.venv/bin/python -m pydoc tools.map_build

The validator checks that every named function has a native docstring and appears in pydoc output. No separate documentation website is maintained for the tools.
