Generator function reference¶

Generated from Python docstrings with Sphinx autodoc. Edit the comments beside the functions in tools/map_build.py to change this reference.

Generate the Qualcomm ecosystem overview and nearby repository views.

The JSON dataset owns repository facts. Markdown, SVG, and exported nearby views are derived outputs. The generator runs without network access.

map_build.build(data: dict, digest: str) → None¶

Generate the overview and every repository’s nearby Markdown/SVG pair.

Parameters:

  • data – Validated dataset.

  • digest – SHA-256 identifying the dataset used for generated views.

Returns:

None; writes deterministic output under docs/source/.generated.

Raises:

OSError – If generated files cannot be written.

Example: build(load_data(DATA), hashlib.sha256(DATA.read_bytes()).hexdigest()).

map_build.diagram(nodes: list[dict], edges: list[dict], focus: str) → str¶

Render an accessible SVG showing directed relationships around one repo.

Parameters:

  • nodes – Selected repository records.

  • edges – Incident relationship records.

  • focus – Identifier to highlight as the reader’s current repository.

Returns:

Self-contained SVG text with labels and no external assets.

Example: diagram(*nearby(load_data(DATA), 'qualcomm-linux/meta-qcom'), 'qualcomm-linux/meta-qcom').

map_build.load_data(path: Path) → dict¶

Read and validate a dataset before producing any output.

Parameters:

path – JSON dataset path.

Returns:

Parsed dataset with valid unique repositories and evidenced edges.

Raises:

  • ValueError – For invalid IDs, duplicate edges, or missing evidence.

  • OSError – If the dataset cannot be read.

Example: load_data(DATA)['schema_version'] returns 1.

map_build.main() → None¶

Build all views or export one nearby view into a repository’s docs.

Returns:

None; writes generated files and prints a coverage summary.

Raises:

  • SystemExit – For invalid command-line arguments.

  • ValueError – For invalid source data or export revisions.

Example: python tools/map_build.py --export qualcomm-linux/meta-qcom-3rdparty --destination /tmp/nearby --revision <commit>.

map_build.nearby(data: dict, focus: str) → tuple[list[dict], list[dict]]¶

Select the focus repository and all recorded incoming/outgoing neighbours.

Parameters:

  • data – Validated dataset.

  • focus – Exact owner/repository identifier.

Returns:

Selected repositories and incident relationships, in stable order.

Raises:

KeyError – If the focus repository is absent.

Example: nearby(load_data(DATA), 'qualcomm-linux/meta-qcom-3rdparty') selects its local view.

map_build.relation_table(edges: list[dict]) → str¶

Format direction, applicability, and source evidence for relationships.

Parameters:

edges – Validated relationship records.

Returns:

Markdown table with one row per relationship.

Example: relation_table([]) returns a table header with no data rows.

map_build.render_view(data: dict, focus: str, image_name: str, digest: str, revision: str | None = None) → str¶

Generate a nearby view from the shared data, including revision provenance.

Parameters:

  • data – Validated dataset.

  • focus – Current repository identifier.

  • image_name – Relative SVG filename beside this Markdown page.

  • digest – SHA-256 of the source dataset.

  • revision – Optional central repository commit used by an exported view.

Returns:

Markdown guide with a map, relationship evidence, and navigation.

Example: render_view(load_data(DATA), 'qualcomm-linux/meta-qcom-3rdparty', 'map.svg', 'digest').

map_build.slug(identifier: str) → str¶

Return a filesystem-safe name for an owner/repository identifier.

Parameters:

identifier – Repository identifier, such as qualcomm-linux/meta-qcom.

Returns:

Identifier with the slash replaced by two hyphens.

Raises:

ValueError – If the identifier contains unsupported characters.

Example: slug('qualcomm-linux/meta-qcom') returns 'qualcomm-linux--meta-qcom'.
